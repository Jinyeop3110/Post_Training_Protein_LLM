1. Context

We use Qwen3-8B-Instruct as the base LLM for our protein post-training pipeline. After supervised fine-tuning (SFT), we apply GRPO (Group Relative Policy Optimization) to align the model with verifiable downstream task rewards—GO term prediction, protein stability, protein-protein interactions, and structural quality.

Qwen3-Instruct models have a built-in thinking mode that generates <think>...</think> reasoning blocks before producing the final answer. This creates a subtle design decision for GRPO that is easy to get wrong.

The core tension Our SFT was trained without reasoning traces—no thinking data exists in our 4.89M-sample training set. Every training example uses enable_thinking=False, producing empty <think>\n\n</think> blocks. The model has learned to skip reasoning and answer directly. Now we need to decide what to do during GRPO rollouts.

2. The Subtlety of Qwen3 Thinking Mode

Thinking mode in Qwen3 is more nuanced than a simple on/off switch. There are four key points to understand:

2.1. enable_thinking controls the chat template, not the model

The enable_thinking=True/False parameter in apply_chat_template() controls what text the template prefills in the assistant turn. It does not modify the model weights or attention patterns.

Setting Template Output (after <|im_start|>assistant\n) Effect
enable_thinking=True (default) (nothing prefilled—model decides) Model generates <think>...</think> then answer
enable_thinking=False <think>\n\n</think>\n\n Model sees empty thinking block, generates answer directly

Source: Qwen3 Chat Template Deep Dive

2.2. /think and /no_think are NOT special tokens

The /think and /no_think switches that appear in Qwen3 documentation are behavioral soft switches embedded as plain text in the user message. They are not tokenizer-level special tokens like <|im_start|>. They function only when enable_thinking=True and work by influencing the model's generation behavior through in-context instruction following, not through any hard-coded mechanism.

2.3. You cannot truly "turn off" thinking

Critical nuance: Even with enable_thinking=False, Qwen3 may still prepend <think> tokens during generation. Thinking is a learned behavior deeply embedded in the model's weights from its training pipeline, not a hard gate. The empty <think>\n\n</think> prefill strongly suppresses reasoning (the model has learned to continue past empty thinking blocks), but it is not an absolute guarantee. This is why our reward extraction code has a fallback path that strips <think> blocks even when thinking is nominally disabled.

2.4. The SFT precedent constrains GRPO

Our SFT model was trained on 4.89M samples, all with empty <think></think> blocks. The model has thoroughly learned the pattern: see empty thinking, produce a direct answer. Enabling thinking in GRPO would ask the model to discover protein reasoning from scratch via RL alone—this is the DeepSeek-R1-Zero approach, which works for math/coding but is untested for protein biology.

DeepSeek-R1's Four Stages DeepSeek-R1 does not jump straight to reasoning RL. Their pipeline is:
  1. Long CoT cold-start SFT: Train with reasoning traces first
  2. Reasoning RL: GRPO with thinking enabled (model already knows how to reason)
  3. Thinking mode fusion: Blend reasoning + non-reasoning data
  4. General RL: Final GRPO across all tasks
We are at step 1 without reasoning data. Jumping to step 2 would skip the foundation.

3. Three Options Considered

Option A: Enable + Train All

Enable thinking, train on full output including <think> blocks.

Risks training on garbage reasoning since SFT had none.

REJECTED

Option B: Disable + Suppress

enable_thinking=False, prepend empty <think>\n\n</think>\n\n to suppress reasoning.

Model generates directly. All token budget goes to the answer.

SELECTED

Option C: Enable + Mask Loss

Enable thinking but mask <think> tokens from GRPO policy gradient loss.

Only answer tokens get gradient signal. Most complex to implement.

FUTURE OPTION

Option A: Enable Thinking, Train on Full Output

With enable_thinking=True (the default), the model generates a <think>...</think> block followed by the answer. GRPO loss is computed on all generated tokens, including the reasoning.

The problem: our SFT model has no reasoning capability for protein tasks. The <think> blocks would contain incoherent, repetitive, or hallucinated text. GRPO would then try to optimize these garbage reasoning traces, likely leading to reward hacking or training instability. We saw exactly this behavior when evaluating the base (non-SFT) Qwen3 model—it got stuck in endless <think> chains that consumed the entire token budget without ever producing an answer.

Option B: Disable Thinking, Suppress with Empty Prefix

# In _generate_completions() — text-only path:
wrapped_prompt = self.tokenizer.apply_chat_template(
    messages, tokenize=False, add_generation_prompt=True,
)
# Append empty thinking prefix: model generates after it
wrapped_prompt += _THINKING_PREFIX   # "<think>\n\n</think>\n\n"

The empty thinking prefix signals the model that reasoning is complete. All max_new_tokens are available for the answer. This matches the regime the model learned during SFT.

Option C: Enable Thinking, Mask from GRPO Loss

The most surgical approach: let the model generate <think> blocks freely, but compute log_probs only for tokens after </think>. Thinking tokens receive zero gradient—the model is only optimized on answer quality.

This is supported by the "Do Thinking Tokens Help or Trap?" paper (arXiv:2506.23840), which found that masking thinking tokens from GRPO loss yields better results for structured output tasks. However, implementation is complex: it requires finding the </think> boundary in each generated sequence and applying per-token masks to the log probability computation.

4. Our Decision: Option B + Structured <answer> Tags

We adopt Option B (disable thinking entirely) with an enhancement inspired by DeepSeek-R1: structured <answer> tags and a format reward.

The Design

  • Disable thinking: SFT baseline has no reasoning capability to build on. Enabling it would train on degenerate traces.
  • System prompt instructs <answer> tag usage: "Always wrap your final answer in <answer> and </answer> tags."
  • Format reward bonus (0.1): The model receives a small bonus for correctly wrapping output in <answer> tags, encouraging consistent structured output.
  • Reward functions evaluate only tag content: Content inside <answer>...</answer> is extracted and passed to the task-specific reward function (GO F1, stability MAE, etc.).
  • Fallback: If no <answer> tags are found, strip any <think> blocks and evaluate the full text. This handles early training steps before the model learns the tag format.
GRPO Rollout Pipeline

System prompt: "You are a protein expert... Always wrap your final answer in <answer> tags."
↓
enable_thinking=False → empty <think></think> prefill appended to prompt
↓
Model generates: <answer>GO:0005524, GO:0006468, GO:0004672</answer>
↓
extract_answer_content() → "GO:0005524, GO:0006468, GO:0004672" (has_tags=True)
↓
Task reward: compute_go_reward(answer, ground_truth) + Format bonus: 0.1
↓
GRPO loss on all generated tokens (answer only, no thinking waste)

5. Why This Matters

Thinking mode in RL is not just a config flag. It affects three critical aspects of the training pipeline:

5.1. Loss Computation

GRPO computes policy gradient loss on all generated tokens. With thinking enabled, the loss includes gradient signal for reasoning tokens that the model produces randomly (since it was never trained to reason about proteins). This creates a noisy, potentially destabilizing training signal. The optimizer would spend gradient budget trying to improve meaningless reasoning rather than improving answer quality.

5.2. Reward Extraction

Our reward functions use regex to extract values from generated text (GO terms, pLDDT scores, Yes/No predictions). With thinking enabled, the <think> block could contain numbers, GO terms, or keywords that the reward parser accidentally matches:

# ESMFold reward extracts pLDDT from response:
plddt_patterns = [r"plddt[:\s]+(\d+\.?\d*)", ...]

# With thinking: "<think>The pLDDT might be around 60...</think>
# Fold quality: high. pLDDT: 85."
# Could match "60" from thinking instead of "85" from answer!

5.3. Token Budget Competition

With thinking enabled, the model must allocate its max_new_tokens between reasoning and answer:

Task max_new_tokens Typical Answer Risk with Thinking
GO Prediction 256 ~30 tokens ~226 tokens wasted on reasoning
Structure Quality 256 ~40 tokens ~216 tokens wasted on reasoning
ProteinLM Bench 64 ~5 tokens ("option 2") Thinking consumes entire budget; answer truncated

For ProteinLM Bench with only 64 max tokens, thinking could easily consume the entire budget before the model produces an answer, resulting in truncated output and zero reward.

5.4. Training Stability

Without thinking data in SFT, enabling thinking in RL would force the model to generate from a distribution it has never been trained on. This distribution shift between the SFT policy and the GRPO rollout policy increases KL divergence, making the RL optimization harder to control and more prone to reward hacking or mode collapse.

Bottom line: Thinking mode is not just a flag—it affects loss computation, reward extraction, token budgets, and training stability. Without reasoning-annotated protein data, disabling thinking is the only safe choice.

6. Implementation Details

The implementation spans two files:

src/training/rewards.py

# Regex patterns for tag extraction
_THINK_RE = re.compile(r"<think>.*?</think>", re.DOTALL)
_ANSWER_RE = re.compile(r"<answer>(.*?)</answer>", re.DOTALL)

# Format reward for using <answer> tags correctly
FORMAT_REWARD_BONUS = 0.1

def extract_answer_content(text: str) -> Tuple[str, bool]:
    """Extract content from <answer>...</answer> tags.

    Returns (extracted_text, has_answer_tags).
    If <answer> tags found, returns content inside them.
    Otherwise strips <think> tags and returns full text (fallback).
    """
    clean = _strip_think_tags(text)
    match = _ANSWER_RE.search(clean)
    if match:
        return match.group(1).strip(), True
    return clean, False

src/training/grpo_trainer.py

# GRPO Prompt Constants
_GRPO_ANSWER_SUFFIX = " Always wrap your final answer in <answer> and </answer> tags."
_THINKING_PREFIX = "<think>\n\n</think>\n\n"

# In _generate_completions():
# 1. Build GRPO system prompt (base protein expert prompt + answer tag instruction)
grpo_system_prompt = DEFAULT_SYSTEM_PROMPT + _GRPO_ANSWER_SUFFIX

# 2. Text-only path: append empty thinking prefix to generation prompt
wrapped_prompt = self.tokenizer.apply_chat_template(
    messages, tokenize=False, add_generation_prompt=True,
)
wrapped_prompt += _THINKING_PREFIX   # Model generates after empty <think></think>

# 3. Multimodal path: pass system_prompt to ProteinLLM.generate()
texts = self.protein_llm.generate(
    protein_sequences=batch_proteins,
    prompt=batch_prompts,
    system_prompt=grpo_system_prompt,   # Includes answer tag instruction
    **gen_kwargs,
)

# In _compute_rewards():
answer_text, has_answer_tags = extract_answer_content(completion)
reward = self.reward_fn(answer_text, ground_truth)
format_bonus = FORMAT_REWARD_BONUS if has_answer_tags else 0.0
reward += format_bonus

7. Future Path

Once we have reasoning-annotated protein data, we can revisit enabling thinking with proper traces. The path forward follows DeepSeek-R1's staged approach:

Stage 1 (current): SFT without thinking → GRPO without thinking
↓
Stage 2 (future): Generate reasoning traces with a teacher model (e.g., Qwen3-32B)
↓
Stage 3: CoT SFT with reasoning data (<think>reasoning</think> + answer)
↓
Stage 4: GRPO with enable_thinking=True, strip <think> before reward
Model already knows how to reason → RL refines which reasoning leads to correct answers

At that point, Option C (masking thinking tokens from GRPO loss) becomes worth revisiting. The "Do Thinking Tokens Help or Trap?" paper found that for structured output tasks, masking is better than including thinking in the loss. But this only matters once the model actually generates meaningful reasoning.
