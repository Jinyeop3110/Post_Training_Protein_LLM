From 22.7 to 1.4 Perplexity: What SFT Actually Teaches a Protein LLM

2026-03-09 · Post-Training Protein LLM Project
evaluation sft baseline milestone

TL;DR

We evaluated the base Qwen3-8B model (zero-shot, no fine-tuning) on our protein SFT evaluation set and compared it against our fine-tuned MLP and Text SFT models. The results are dramatic:

28.3 ESM-3 + Random PPL
22.7 Base Text PPL
3.4 Text SFT PPL
1.4 MLP SFT PPL

The base Qwen3-8B has 22.7 perplexity on protein tasks — and injecting random ESM-3 embeddings makes it worse (28.3). Only a trained projector unlocks the encoder's value, driving perplexity down to 1.4 — a 19.8x improvement over the random baseline. This confirms that the MLP projector learns genuine biological signal from ESM-3, not just extra parameters.

The Experiment

We ran the base Qwen3-8B-Instruct-2507 model (no fine-tuning, no adapter) through our standard SFT evaluation pipeline on 5,000 samples from the combined protein dataset. The evaluation measures:

  1. Perplexity — How surprised is the model by the reference answers? (lower = better)
  2. Generation quality — BLEU and ROUGE-L on 200 generated samples across task categories (catalytic, domain, function, general)

We compare against our two fine-tuned models: the ESM-3 + MLP projector SFT (best eval_loss at step 9,750/28,941) and the Text-only SFT (best eval_loss at step 6,750/9,647). Neither model has finished training, so these are intermediate results. The fine-tuned eval_loss values come from the training loop validation pass, computed with the same method (cross-entropy on response tokens only).

Key finding: The MLP SFT achieves 15.9x lower perplexity than the base model, and 2.4x lower than Text SFT, despite being only 34% through training. ESM-3 protein embeddings carry dense biological information that text tokens alone cannot match at this data efficiency.

Why the Eval Loss Gap Between MLP and Text Is So Large

The MLP model's eval_loss (0.36) is dramatically lower than Text's (1.23). This isn't a fair apples-to-apples comparison — they solve fundamentally different tasks:

  • MLP (eval_loss 0.36): The model receives pre-computed ESM-3 embeddings (32 tokens of dense protein features) and only needs to predict the text answer. The protein "understanding" is handed to it for free by the frozen encoder.
  • Text (eval_loss 1.23): The model must tokenize the raw amino acid sequence (often 200-1000+ characters), parse it, and then generate the answer. It handles both protein comprehension and answer generation in the same forward pass.

The eval_loss comparison is still meaningful: it shows that ESM-3 embeddings are a much more efficient representation of protein information than raw text tokens. The MLP model needs far less capacity to decode the right answer because the encoder has already extracted the relevant features.

Both models fail on highly specific expression regulation data. This is a memorization task — the answer is organism-specific experimental data that neither model can infer from sequence alone. These failures reveal the limits of what SFT can teach.

What the Base Model Gets Wrong

The base Qwen3-8B model (no fine-tuning) has a perplexity of 22.73 and generation BLEU of 0.003 on our protein tasks. The generation score is effectively zero — 85x worse than our fine-tuned models.

The root cause is devastating: 0 out of 200 base model generations produced an actual answer. Every single generation gets stuck in Qwen3's <think> chain-of-thought mode, reasoning about the protein sequence endlessly without ever producing a </think> closing tag:

Base Model Output (Catalytic Activity Task)
<think>
Okay, let's tackle this protein sequence analysis. The user wants to know the catalytic activity of the enzyme, specifically the chemical reaction it catalyzes. First, I need to look at the sequence provided. It's a long string of amino acids, so I should start by checking for any obvious mo...
[truncated at max_new_tokens — never reaches </think>]

This reveals three compounding failures:

  • Thinking mode trap — Qwen3-Instruct models default to chain-of-thought reasoning. Without SFT training that includes <think></think> patterns, the model never learns to stop reasoning and start answering.
  • No domain knowledge — Even within the thinking block, the model's reasoning is generic ("let me look at the sequence...") rather than biologically informed. It cannot actually analyze amino acid sequences.
  • Format mismatch — The base model has no concept of the expected output formats (reaction equations, domain names, GO terms). SFT teaches both the format and the content.

The tiny non-zero ROUGE-L (0.061) comes from occasional token overlaps between the thinking text and reference answers, not from actual correct predictions.

Key Takeaways

  1. SFT is essential, not optional. Base Qwen3-8B perplexity (22.7) is 6.6-15.9x worse than fine-tuned models. A general LLM simply cannot do protein tasks without domain-specific training.
  2. ESM-3 embeddings dramatically improve perplexity (1.43 vs 3.43 for text). The frozen encoder provides a "free" protein understanding module that reduces the LLM's burden to just decoding the answer.
  3. Perplexity and generation quality don't perfectly correlate. MLP has 2.4x better perplexity but similar BLEU/ROUGE-L to Text SFT. This suggests the MLP model is more confident on average but not necessarily more accurate on the hardest examples.
  4. Different architectures have different strengths. MLP excels at function descriptions (+0.11 BLEU) and consistently achieves higher ROUGE-L, while Text SFT is competitive or better on catalytic activity and domain identification (where exact sequence details may matter more).
  5. The 32-token bottleneck is real. MLP sometimes hallucinates wrong protein families despite having low perplexity. The attention pooling from ~500 encoder tokens down to 32 tokens loses fine-grained sequence identity information.
