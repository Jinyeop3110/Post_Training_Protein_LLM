RL Benchmark Expansion: Overlap Analysis & Implementation Plan

Date: 2026-03-16 | Question: Which new benchmarks can we add as GRPO reward tasks without SFT data contamination?

Source: Protein-LLM-Survey (Yijia-Xiao/Protein-LLM-Survey) benchmark catalog

grporlevaluationdatamilestone

Executive Summary

We surveyed 4 candidate benchmarks from the Protein-LLM-Survey for new GRPO reward tasks. SFT data overlap analysis identified 2 clean tasks for implementation: solubility prediction (<0.2% contamination) and fold classification (<0.5% contamination). EC number prediction is skipped due to ~15% contamination in our 4.89M SFT dataset. Fitness/DMS prediction is deferred as partly redundant with the existing stability/ddG task. This expands our GRPO reward suite from 3 active tasks to 5.

3. SFT Data Overlap Analysis

We checked sequence-level overlap between each candidate benchmark and our 4.89M SFT training dataset (6 sources: Mol-Instructions, UniProt-derived, PDB, Swiss-Prot subsets). Contamination = fraction of benchmark sequences that appear in SFT training data.

Benchmark Contamination Rate Overlap Source Severity Decision
EC Number Prediction ~15% Swiss-Prot sequences shared with Mol-Instructions enzyme function tasks High SKIP
Fold Classification <0.5% Minimal — CATH/SCOPe structural domains rarely in text-based SFT data Low IMPLEMENT
Solubility Prediction <0.2% Negligible — eSOL/DeepLoc datasets not represented in Mol-Instructions Excellent IMPLEMENT
Fitness / DMS 3–4% Some overlap with MegaScale stability data; also partly redundant with existing ddG task Moderate DEFER
EC Number: ~15% contamination — too high for reliable GRPO evaluation.
The Swiss-Prot enzyme function annotations overlap significantly with Mol-Instructions enzyme-related QA pairs. A model trained on these SFT examples could achieve high EC reward by memorizing rather than reasoning. This invalidates the reward signal.
Fold Classification: <0.5% contamination — clean for GRPO.
CATH/SCOPe structural fold assignments are derived from 3D structure analysis, not from the text-based protein descriptions in our SFT data. Minimal overlap because structural classification is underrepresented in Mol-Instructions.
Solubility: <0.2% contamination — excellent for GRPO.
eSOL (experimental) and DeepLoc (predicted) solubility labels come from specialized experiments/databases not present in our SFT sources. This is the cleanest candidate.
Fitness/DMS: 3–4% contamination + redundancy with stability task.
ProteinGym variants overlap with MegaScale stability data already used in our ddG GRPO task. Adding this would provide marginal new signal while complicating the reward landscape. Deferred until we exhaust the cleaner options.

4. Decision Summary

Implement 2 new GRPO tasks:
  1. Solubility Prediction — binary classification (soluble/insoluble) with optional regression component for continuous solubility scores
  2. Fold Classification — exact-match reward with hierarchical partial credit across 4 CATH levels (Class > Architecture > Topology > Homology)
Skip: EC Number Prediction (15% contamination)
Defer: Fitness/DMS Prediction (redundant with stability task)

This expands the GRPO reward suite from 3 tasks (GO, stability, structure) to 5 tasks (+ solubility, fold classification).

6. Implementation Plan

6a. Solubility Prediction Task

Reward design: Binary classification (soluble vs insoluble) + optional regression component.

  • Format reward (0.1): Response follows expected output format
  • Classification reward (0.5): Exact match on soluble/insoluble binary label
  • Regression reward (0.4): Closeness of predicted solubility score to experimental value (if model outputs a numerical score)
Files to create/modify: scripts/data/download_solubility.py — Download eSOL + DeepLoc, merge, format as JSON configs/data/solubility.yaml — Dataset config (paths, splits, max_samples) configs/main_RL/grpo_solubility.yaml — GRPO config (reward_type: solubility, system prompt) src/training/rewards.py — Add compute_solubility_reward(), register as "solubility" src/training/grpo_trainer.py — Add solubility system prompt, metadata routing for ground truth CLAUDE.md — Update quick reference with new task command

6b. Fold Classification Task

Reward design: Exact-match with hierarchical partial credit across CATH levels.

  • Format reward (0.1): Response follows expected output format
  • Hierarchical match reward (0.9): Partial credit at each CATH level:
    • Class match (level 1): +0.225 (25% of 0.9)
    • Architecture match (level 2): +0.225
    • Topology match (level 3): +0.225
    • Homology match (level 4): +0.225 (full match)

This rewards models that get the broad structural class right even if they miss the fine-grained homology level.

Files to create/modify: scripts/data/download_fold_classification.py — Download CATH domain assignments, format as JSON configs/data/fold_classification.yaml — Dataset config configs/main_RL/grpo_fold_classification.yaml — GRPO config (reward_type: fold_classification) src/training/rewards.py — Add compute_fold_reward(), register as "fold_classification" src/training/grpo_trainer.py — Add fold classification system prompt, CATH metadata routing CLAUDE.md — Update quick reference

7. Recommendations

  1. Implement solubility first — simplest reward design (binary classification), cleanest data (<0.2% contamination), fastest to validate.
  2. Fold classification second — hierarchical partial credit requires more careful reward engineering but provides richer signal.
  3. Target 10K samples each — consistent with existing downstream tasks (GO, stability, structure all use 10K).
  4. Run both Text and MLP variants — given the SFT-to-GRPO paradox (text beats MLP on structure despite worse SFT loss), we need both approaches for every new task.
  5. Use frozen-MM config for MLP runs — standard MLP suffers from LoRA gradient death in GRPO; frozen-MM is the proven workaround (0.774 vs 0.582 mean_reward on structure).
  6. Re-evaluate EC number later — if we retrain SFT without Swiss-Prot enzyme QA pairs, EC number becomes viable. Not worth it now.
  7. Consider multi-task GRPO — with 5 tasks available, training on a mixture of rewards could improve generalization vs single-task GRPO.
