Figure Upgrade Proposal: Closing the Gap to a Publication-Ready Figure Set

Date: 2026-03-09  |  Question: What figures need to be created, updated, or replaced for a complete paper?  |  Scope: 9 main figures, 50 supplementary blog figures, 30 paper supplementary figures

1. Executive Summary

The project has 9 main figures (fig1–fig9) and ~50 supplementary blog figures, all generated through a unified style system (figure_style.py). However, several critical gaps prevent the current set from being paper-ready:

  • Missing approaches: Figures 8 and 9 only cover 2 of 4 approaches (MLP and Text-only). Perceiver SFT on 4.89M (sft_esm3_perceiver_combined_qwen3_8b_it_0308_165601) has no checkpoints or metrics yet, and Flamingo has not been run. The four-way comparison thesis remains incomplete.
  • Stale data in Fig 8: The Text-only curve in fig8_mlp_vs_text.png shows only ~200 steps of data (the run was still early at snapshot time), making the comparison visually misleading—the text line terminates prematurely while MLP extends to 9,750 steps.
  • No downstream evaluation figures: Base model evaluation exists (BLEU 0.003, ROUGE-L 0.057 for ESM3; BLEU 0.003, ROUGE-L 0.061 for Text) but no figures visualize the SFT vs base model improvement or per-task breakdown.
  • No GRPO figures: Two GRPO runs launched 2026-03-09 (grpo_structure_mlp_sft_*) but produced no checkpoints or metrics yet.
  • Generation quality uses hardcoded fallbacks: fig6_generation_quality.png displays Step 7000 data from fallback constants, not from the actual generation_step_9750.json which shows BLEU 0.256 / ROUGE-L 0.481 (lower than fallback 0.307 / 0.483).

7. Technical Debt in Figure Generation

Hardcoded fallbacks in plot_pub_figures.py

Three sets of fallback data are defined at module level:

  • _FINAL_METRICS_FALLBACK: Used by fig9 when analysis_summary.json is missing or incomplete
  • _GEN_METRICS_FALLBACK: Used by fig6 always (no loader for generation eval JSONs)
  • _DATASET_COMP_FALLBACK: Used by fig3 always (no dataset metadata loader)

The load_metrics() function tries to read from analysis_summary.json for final metrics but always falls through to fallbacks for generation and dataset composition. This is the root cause of fig6 showing wrong numbers.

Text run data not in CSV snapshots

The run_histories.csv in blog/data/03-07/ only contains partial text run data because the data snapshot was taken before sft_text_combined_qwen3_8b_it_0307_190324 completed. The 03-09 metadata file confirms 700 log entries (10 steps per entry = 7,000 total steps), but the CSV was not refreshed.
