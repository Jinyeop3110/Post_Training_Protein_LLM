1. Overview: Expanding the GRPO Task Suite

We added two new GRPO reward tasks—solubility prediction (eSOL, binary+regression) and fold classification (CATH, hierarchical 4-level)—expanding the RL training suite from 3 tasks to 7+ tasks. Both have clean SFT contamination profiles, verified reward functions, and complete pipeline integration.

Why these tasks? After surveying the Protein-LLM-Survey benchmark catalog, we selected solubility and fold classification based on three criteria: (a) verifiable ground truth for reward computation, (b) available at scale (5K+ samples), and (c) minimal overlap with our 4.89M SFT training data. EC number prediction was explicitly skipped due to ~15% contamination.

2. SFT Data Contamination Analysis

Before implementing any new GRPO task, we checked sequence-level overlap between each candidate benchmark and our 4.89M SFT training dataset (6 sources: Mol-Instructions, UniProt-derived, PDB, Swiss-Prot subsets). A contaminated RL task is worse than no task at all—the model would get reward for memorization rather than reasoning.

Candidate Task Source Overlap Decision
Solubility eSOL (experimental E. coli) <0.2% GO
Fold Classification CATH domain database <0.5% GO
EC Number Swiss-Prot enzymes ~15% SKIP
Fitness / DMS ProteinGym 3–4% DEFER
EC Number: Contaminated Swiss-Prot enzyme function annotations overlap significantly with Mol-Instructions enzyme-related QA pairs. A model trained on these SFT examples could achieve high EC reward by memorizing rather than reasoning. This invalidates the reward signal. Could revisit if we retrain SFT without Swiss-Prot enzyme QA pairs.
Solubility: Cleanest candidate (<0.2%) eSOL (experimental) and DeepLoc (predicted) solubility labels come from specialized experiments/databases not present in our SFT sources. The solubility prediction task requires genuine protein-feature reasoning.

3. Task 1: Solubility Prediction (eSOL)

3.1 Task Design

Predict protein solubility when expressed in E. coli: binary classification (soluble vs insoluble) plus optional continuous score (0–100%). The threshold is 50%: scores >50% are classified as soluble.

System Prompt (no-think mode)

You are a protein solubility expert. Given a protein amino acid sequence,
predict its solubility when expressed in E. coli.

First write a brief reasoning about the protein's features on a line
starting with "Reasoning:", then give your prediction inside
<answer>...</answer> tags.

Examples:
Reasoning: Small protein, no transmembrane domains, balanced charge. Likely soluble.
<answer>Solubility: soluble. Estimated solubility: 78.5%.</answer>

Reasoning: Large hydrophobic patches, many cysteines, membrane-associated. Likely insoluble.
<answer>Solubility: insoluble. Estimated solubility: 12.3%.</answer>

Expected Output Format

Reasoning: [brief protein feature analysis]
<answer>Solubility: [soluble|insoluble]. Estimated solubility: [X.X]%.</answer>

3.2 Reward Function Design

compute_solubility_reward(generated_text, ground_truth) ├── Classification (weight=0.5) │ ├── Parse predicted class: "soluble" or "insoluble" │ ├── Match ground truth class (threshold at 50%) │ └── Reward: 1.0 (exact match) or 0.0 (mismatch) │ ├── Numerical Accuracy (weight=0.3) │ ├── Extract predicted % from regex patterns: │ │ "solubility: 72.3%", "estimated solubility: 72%", "72.3%" │ ├── Gaussian decay: exp(-0.5 * (error / σ)²), σ=15% │ └── Reward: 1.0 (exact) → 0.0 (far off) │ ├── Format Compliance (weight=0.2) │ ├── Both class + score present: 1.0 │ ├── Class only (no score): 0.5 │ └── Neither: 0.0 │ └── Optional: Focal weighting (gamma=1.0 in config) ├── Class frequencies: soluble=70%, insoluble=30% └── Upweights rare "insoluble" class predictions

Total: reward = 0.5 * classification + 0.3 * numerical + 0.2 * format, optionally scaled by focal weight.

3.3 Trial Run Results

Strong reward signal

Mean reward: 0.644 → 1.584 (2.46x improvement). Format compliance: 100%. The model quickly learned the output structure and began improving classification accuracy.

Focal weighting too aggressive

With focal_gamma=1.0, the reward for correctly predicting insoluble proteins was boosted significantly (insoluble is only 30% of data). This created unstable gradients—the model oscillated between over-predicting insoluble and reverting to majority-class predictions. Recommendation: reduce to focal_gamma=0.5 or disable for initial runs.

Key Observations

  • Binary classification + regression is a natural combination—the model needs both to maximize reward
  • The regex-based score extraction is robust: handles "solubility: 72.3%", "estimated solubility: 72%", and bare "72.3%"
  • Gaussian decay with σ=15% means predictions within ±15% of truth score ≥0.6 reward on the numerical component
  • Unlike the collapsed structure quality task, solubility has genuine per-protein variation (each protein has a unique score)

4. Task 2: Fold Classification (CATH)

4.1 Task Design

Predict a protein's CATH structural classification at four hierarchical levels: Class (C), Architecture (A), Topology (T), and Homology (H). The reward gives partial credit: 0.25 per correct level, evaluated top-down with early stopping at the first mismatch.

CATH Classes

CodeNameDescription
1Mainly AlphaPredominantly alpha-helical proteins
2Mainly BetaPredominantly beta-sheet proteins
3Alpha BetaMixed alpha/beta structures
4Few Secondary StructuresIrregular or coil-dominated

System Prompt (no-think mode)

You are a protein structure classification expert. Given a protein amino
acid sequence, predict its CATH structural classification at four levels:
Class (C), Architecture (A), Topology (T), and Homology (H).

CATH classes: 1=Mainly Alpha, 2=Mainly Beta, 3=Alpha Beta,
4=Few Secondary Structures.

First write a brief reasoning about the protein's structural features on a line
starting with "Reasoning:", then give the CATH code inside
<answer>...</answer> tags.

Examples:
Reasoning: Helical bundle pattern, globin-like fold. Class 1, orthogonal bundle.
<answer>CATH: 1.10.490.10. Class: Mainly Alpha. Architecture: Orthogonal Bundle.
Topology: Globin-like. Homology: Globin.</answer>

Reasoning: Beta sandwich with immunoglobulin topology. Class 2.
<answer>CATH: 2.60.40.10. Class: Mainly Beta. Architecture: Sandwich.
Topology: Immunoglobulin-like. Homology: Immunoglobulin.</answer>

4.2 Reward Function Design

compute_fold_classification_reward(generated_text, ground_truth) ├── Parse ground truth CATH code (e.g., "1.10.490.10") │ └── Split into 4 levels: [1, 10, 490, 10] │ ├── Parse prediction — two strategies: │ ├── Primary: extract dotted CATH code via regex (\d+\.\d+\.\d+\.\d+) │ └── Fallback: match class by name ("mainly alpha" → 1, "mainly beta" → 2, etc.) │ ├── Hierarchical comparison (top-down, stop at first mismatch): │ ├── Level 1 (Class): match? → +0.25 │ ├── Level 2 (Architecture): match? → +0.25 │ ├── Level 3 (Topology): match? → +0.25 │ └── Level 4 (Homology): match? → +0.25 │ └── Total reward: sum of matched levels × 0.25 ├── All 4 match: 1.00 ├── Class only: 0.25 ├── Class+Arch: 0.50 ├── Class+Arch+Topo: 0.75 └── No match: 0.00

Key design choice: Hierarchical early stopping. If the model gets the class wrong (e.g., predicts "Mainly Alpha" for a beta protein), it gets 0 even if lower levels happen to match numerically. This enforces correct top-level reasoning before rewarding specificity.

4.3 Trial Run Results

Modest improvement, class-level only

Mean reward: 0.265 → 0.340 (+28%). Format compliance: 100%. The model consistently achieves class-level matches (0.25 reward) but rarely gets architecture or deeper levels correct. This is expected—predicting topology and homology from sequence alone is extremely challenging, even for specialized models.

Key Observations

  • Class-level matches only: The model learned to distinguish alpha vs beta vs mixed proteins (the "easy" first level), but couldn't predict specific architectures or topologies from sequence text alone
  • Synthetic data caveat: CATH annotations were downloaded from HuggingFace rather than direct CATH database queries, so some topology/homology labels may have artifacts
  • No focal weighting needed—CATH classes are more balanced than solubility (disabled in config)
  • Reward ceiling is effectively ~0.25–0.50 for text-only approach; the ESM-3 multimodal path should perform better as structural features are directly encoded
  • The fallback name-matching in the reward function ("mainly alpha", "all alpha", "alpha-beta") provides partial credit even when the model doesn't output a formal CATH code

5.3 Focal Weighting (Solubility)

Solubility data has a 70/30 split (soluble vs insoluble). Focal weighting upweights the minority class:

_SOLUBILITY_CLASS_FREQ = {"soluble": 0.70, "insoluble": 0.30}

# With gamma=1.0:
#   soluble:   focal_weight = (1 - 0.70)^1.0 = 0.30
#   insoluble: focal_weight = (1 - 0.30)^1.0 = 0.70
# → insoluble predictions get 2.3x more reward weight
Lesson learned: gamma=1.0 was too aggressive The 2.3x boost for insoluble predictions caused reward oscillation in the trial run. The model would overpredict "insoluble" to chase the higher focal weight, then snap back when classification accuracy dropped. Recommended fix: focal_gamma=0.5 (1.5x boost) or disable entirely for the initial run.

8. Next Steps

  1. Re-run solubility with reduced focal: Set focal_gamma=0.5 (or disable) and compare reward trajectories. The strong initial signal suggests this task has real learning potential.
  2. Add ESM-3 variants: Create grpo_solubility_mlp_sft.yaml and grpo_fold_classification_mlp_sft.yaml configs for multimodal runs. Fold classification especially should benefit from structural embeddings.
  3. Generate structure properties data: Run python scripts/data/download_structure_properties.py --task composition and --task per_residue to unblock tasks 4–5.
  4. Launch GO + Stability GRPO: These have been ready since initial implementation but haven't been run yet. Priority for the text vs MLP comparison.
  5. Multi-task GRPO: With 7+ tasks available, explore reward aggregation (alternating tasks per batch, or weighted multi-reward).
  6. Investigate fold classification ceiling: The 0.25–0.50 reward range for text-only suggests a hard ceiling. Test whether ESM-3 embeddings break through to architecture-level (0.50+) predictions.
