1. The Output Collapse Problem

Our current GRPO structure quality task has a fundamental flaw: the text model achieves 0.832 mean reward by memorizing two templates, not by understanding proteins. Across 13 GRPO experiments (9 completed), every text-only run converges to the same degenerate behavior.

Evidence: Two Templates for Every Protein

Probe completions from grpo_structure_text_sft_0312_032738 show the text model producing identical reasoning for 5 completely different proteins at step 25:

5 different proteins — Step 25 
MAAVDDLQFE... → "Strong hydrophobic core, regular secondary structure. High confidence ~88."
MRHRKSGRQL... → "Strong hydrophobic core, regular secondary structure. High confidence ~92."
MSELEKAMVA... → "Strong hydrophobic core, regular secondary structure. High confidence ~90."
MTVSTNAVVI... → "Strong hydrophobic core, regular secondary structure. High confidence ~84."
MPMTLGYWDI... → "Strong hydrophobic core, regular secondary structure. High confidence ~95."

By step 50, the model learned one additional template: "Mixed ordered/disordered regions. N-terminal structured, C-terminal flexible." It now alternates between exactly 2 templates for all proteins. The pLDDT number varies slightly (84–95); everything else is copied verbatim from the system prompt example.

Reward hacking, not learning

PG loss converges to near zero by step 25 — the policy is fully deterministic. The model discovered that most proteins in the dataset are well-folded (pLDDT 70–90), so always predicting "high quality" is a safe bet. With no KL penalty active (use_kl_penalty=false) and no diversity penalty, GRPO optimizes straight to this shortcut.

Root Causes

  1. Exploitable reward function: Predicting "high quality, pLDDT ~87" scores well because the dataset is skewed toward well-folded proteins.
  2. Protein-agnostic output: The model never needs to inspect the actual sequence. A single template maximizes expected reward across the entire dataset.
  3. No KL constraint: kl_coef=0.1 is set but use_kl_penalty=false, allowing unconstrained drift to degenerate policies.
  4. Coarse granularity: A single "high/medium/low" classification per protein gives minimal signal. One good guess covers most inputs.

2. Why Per-Residue Prediction Solves This

The collapse happens because the current task is protein-level (one category per protein). Per-residue structural property prediction is fundamentally different:

Current Task (Collapsed)

Output: "Fold quality: high. pLDDT: 87."

Granularity: 1 prediction per protein

Hackable? Yes — single template covers 51% of dataset

Protein-specific? No — same output for all inputs

Proposed Task (Per-Residue)

Output: "SS3: H H E E E C C H H H..."

Granularity: L predictions per protein (L = sequence length)

Hackable? No — each protein has a unique SS pattern

Protein-specific? Yes — output must match the actual sequence

Why template copying fails for per-residue prediction

A 200-residue protein has a unique secondary structure pattern (e.g., "H H H E E E E C C H H..."). No single template can score well across proteins with different lengths and folds. The model must analyze the input to produce correct per-residue labels. This creates a dense, sequence-specific reward signal at every position.

Additional Benefits

  • Dense reward signal: Instead of one binary reward per protein, get L per-residue accuracy signals. Much richer gradient information for GRPO.
  • Directly tests encoder quality: ESM-3 embeddings encode structural information. If the projector transmits this to the LLM, per-residue SS3 accuracy should be high for MLP/Perceiver paths.
  • Verifiable ground truth: DSSP/biotite assigns definitive SS labels from coordinates — no ambiguity.
  • Interpretable: We can visually compare predicted vs actual SS patterns, identify where the model fails, and measure per-position accuracy.

3. Three Reward Function Options

We propose three reward function designs, from simplest to most comprehensive:

Option A: Summary Fractions (Simplest)

The model predicts the fraction of each secondary structure type as a structured summary. Reward is based on how close the predicted fractions match the true fractions.

<answer>
Helix: 45%, Strand: 30%, Coil: 25%
</answer>
ComponentWeightScoring
SS fraction accuracy (helix/sheet/coil)0.4Gaussian: exp(-error²/(2×0.15²)), averaged over 3 types
Dominant SS type match0.3Correct classification: helix-rich (>40%), sheet-rich (>30%), mixed, or coil-rich
RSA accuracy0.3Gaussian: exp(-error²/(2×0.1²)) on mean RSA
Pros: Easy to implement, short output, low token cost. Cons: Still protein-level (3 numbers), though harder to hack than current single-category task because three fractions must be internally consistent and match the actual protein. Less protein-specific than per-residue.

The model generates a per-residue secondary structure string. Reward is per-position accuracy.

Recommended approach

Per-residue SS3 is the sweet spot between signal density and output length. For a 200-residue protein, this adds ~400 tokens (space-separated). The reward is impossible to hack with a template because every protein has a unique SS pattern. Q3 accuracy is a well-established metric (Porter 6: 86.6%, NetSurfP-3.0: 85.5%) providing a clear benchmark for our model.

The model predicts multiple per-residue properties. Reward combines SS3 accuracy, RSA correlation, and dihedral angle accuracy.

4. Literature Gap

No existing system uses a general-purpose chat LLM to generate per-residue structural annotations as text. This is a genuine research gap.

Closest Existing Work

SystemYearApproachPer-Residue?Chat LLM?
Prot2Token2024–25 ESM-2 encoder → specialized autoregressive decoder with task tokens Yes (SS, binding sites, 3D coords) No — custom decoder, not a chat model
Porter 62024 ESM-2 embeddings → CBRNN ensemble classifier Yes (SS3: 86.6% Q3, SS8: 76.4% Q8) No — traditional classifier
NetSurfP-3.02022 ESM-1b → CNN + transformer heads Yes (SS + RSA + disorder + dihedrals) No — multi-task prediction head
ESM-32024 4,096-code VQ-VAE structure tokens per residue Yes (structure tokens) No — opaque codebook, not human-readable
ProteinChat / InstructProtein / ProtLLM / ProteinGPT / Evola2023–25 Protein encoder + general-purpose LLM No — all protein-level (function, GO terms, descriptions) Yes
The gap

Specialized models (Prot2Token, Porter 6, NetSurfP-3.0) can predict per-residue structural properties but are not chat models. Chat-based protein-LLMs (ProteinChat, Evola, ProteinGPT) can converse about proteins but only predict protein-level properties. No system combines both: a general-purpose chat LLM generating per-residue structural annotations as natural-language text. Our proposed task would fill this gap.

How ESM-3 Structure Tokens Differ

ESM-3 uses a VQ-VAE with 4,096 discrete structure codes. Each residue gets one token encoding its local 3D neighborhood (16 nearest residues via SE(3)-invariant geometric attention). These tokens are powerful for structure generation but:

  • Opaque: Codebook indices have no human-interpretable meaning.
  • Generation-oriented: Designed for the structure decoder to reconstruct coordinates, not for the LLM to explain structure.
  • Not accessible: In our architecture, the LLM receives projected ESM-3 embeddings, not raw structure tokens.

Our task tests the opposite direction: can the LLM decode structural information from ESM-3 embeddings into human-readable per-residue annotations? This is a test of the projector pathway, not a replacement for structure tokens.

5. Enabling the Four-Way Comparison

Per-residue SS3 prediction is the ideal differentiator for our four encoding approaches because structural information passes through entirely different pathways:

Text-only: Raw AA sequence ("MKTAYIAK...") ──────────────────────────────► Qwen3-8B ──► SS3 No structural info in input. Must infer from sequence alone. Expected baseline: ~65% Q3 (sequence-only methods) ESM3+MLP: AA seq ──► ESM-3 (frozen) ──► AttentionPool(32) ──► MLP ──► Qwen3-8B ──► SS3 ESM-3 embeds encode structure. Pooling compresses L→32 tokens. MLP projects to LLM space. Structure info must survive compression. ESM3+Perceiver: AA seq ──► ESM-3 (frozen) ──► PerceiverResampler(32) ──► Qwen3-8B ──► SS3 Cross-attention preserves more residue-level detail than pooling. Potentially better per-residue accuracy. Flamingo: AA seq ──► ESM-3 (frozen) ──► FlamingoPerceiver(64) ──► GatedCrossAttn ──► SS3 Cross-attention at every 4th LLM layer. No prefix injection. Protein info accessed at multiple depths. Potentially best spatial reasoning.

Predictions

ApproachExpected Q3Rationale
Text-only ~55–65% Must infer structure from raw AA tokens. Baseline for sequence-only methods in the literature is ~65% Q3 with simple models. A general chat LLM without specialized training may be lower.
ESM3+MLP ~65–75% ESM-3 embeddings carry structural information, but attention pooling compresses to 32 tokens, losing per-residue resolution. MLP projection may further blur.
ESM3+Perceiver ~68–78% Cross-attention in Perceiver may preserve more residue-level detail than attention pooling.
Flamingo ~70–80% Multi-layer cross-attention gives the LLM access to protein embeddings at multiple depths, potentially best for spatial reasoning about per-residue properties.
The key test

If MLP/Perceiver/Flamingo paths do not significantly beat text-only on per-residue SS3, it proves the projector pathway is not transmitting structural information effectively — the embeddings are wasted. This is the most direct test of whether the multimodal architecture is working.

Our EsmForProteinFolding wrapper currently extracts only mean pLDDT and pTM. The model returns a much richer set of structural outputs that we can leverage:

Derived Properties (via biotite)

biotite v1.6.0 is already installed and can compute structural properties from in-memory coordinate arrays without external binaries:

PropertyFunctionInputOutput
Secondary structure (SS3) biotite.structure.annotate_sse() AtomArray from atom37 coords Per-residue H/E/C (P-SEA algorithm, >97% agreement with DSSP)
Solvent accessibility (SASA) biotite.structure.sasa() AtomArray Per-residue Å² (Shrake-Rupley rolling probe)
Dihedral angles biotite.structure.dihedral_backbone() AtomArray Per-residue phi/psi/omega (radians)
Contact map Distance matrix on CA atoms AtomArray Binary L×L contact matrix (<8Å threshold)
Key insight: phi/psi and contact maps need no external tool

ESMFold already returns angles (torsion angles) and distogram_logits (distance predictions) as tensors. Only secondary structure assignment and SASA require biotite.

8. Summary & Next Steps

Why this is the right next experiment
  1. Solves collapse: Per-residue output is impossible to hack with a single template.
  2. Tests the architecture: Directly measures whether ESM-3 structural information reaches the LLM through MLP/Perceiver/Flamingo pathways.
  3. Novel contribution: No chat LLM has been trained for per-residue structural prediction. This fills a clear literature gap.
  4. Practical: ESMFold is already in the codebase, biotite is already installed, and the reward function is straightforward to implement.
  5. Benchmarkable: Q3 accuracy is a standard metric with published baselines (Porter 6: 86.6%).

Recommended Path Forward

  1. Start with Option B (per-residue SS3) as the primary reward function.
  2. Limit protein length to ≤256 residues for initial experiments to keep output manageable (~512 tokens for SS3 string).
  3. Run text-only and MLP GRPO first (both have SFT checkpoints ready).
  4. Compare Q3 accuracy: if MLP > text by ≥5% Q3, the projector pathway is working.
  5. Phase in RSA (Option C) once SS3 training is stable.

Open Questions

  • Should we use pre-computed SS3 labels (fast, from data pipeline) or live ESMFold during GRPO (slow, but avoids data staleness)?
  • How to handle proteins shorter than the SS3 prediction length (padding vs truncation)?
  • Should the <think> block be scored (e.g., must mention structural elements) or only the <answer> block?
  • Is biotite's P-SEA algorithm (SS3 only) sufficient, or do we need DSSP (SS8) for richer signal?
